LAB 1 · src/arcade/pong.ts

Ball speed and the bounce angle

Where the ball meets the paddle decides where it goes next. Dead centre sends it straight back. Near the shaded ends sends it off steeply. Each hit also adds a little speed, up to a limit.

 

Move your mouse or finger over the screen to steer the left paddle. Leave it and the autopilot plays.

pong.ts, lines 24 to 32 and 376 to 380

    

    

      

        
Try this

        
    
          
  1. Set Steepest bounce to 0°. Every return goes flat across, so you can't aim. Then try 80°: the ball zig-zags wall to wall.
    2. 
          
  2. Set Computer paddle speed above the ball's top speed. Now it can never miss. That's why the real game keeps it at 80.
    3. 
          
  3. Turn Fixed timestep off, then switch between 30 and 144 pictures a second. The ball changes speed. Turn it back on and the speed stays put. That's lesson A in action.
    4. 
        

      

      

        
Where it came from

        
    
          
  • Tennis for Two (1958) ran on an oscilloscope. It was the first bat-and-ball game on a screen.
    • 
          
  • Pong (1972) split each paddle into 8 zones, and each zone sent the ball off at a set angle. Our game does the same thing, but smoothly: the angle grows steadily from the middle to the edge.
    • 
          
  • Breakout (1976) used the same "aim with the paddle edge" trick against a wall of bricks.

      LAB 2 · src/arcade/flyover.ts + flyover-data.ts
      
Climb, sink and drag

      
The climb key doesn't move the plane up directly. It pushes on the plane's up-speed. Drag (air resistance) bleeds some of that speed away every moment. That's why the plane eases into a climb and keeps drifting for a moment after you let go. The white line is the height trail, so you can see the curve.

You can also hold Space or the Up arrow, or press on the screen. Holding Down dives. Pressing climb switches the autopilot off.

Try this

        
    
          
  1. Pick the Jumbo and give it one short climb. Watch how long the trail keeps rising after you let go. That's low drag (1.4) doing its job.
    2. 
          
  2. Set Drag to 0. The plane only stops at its speed limits, so it feels like flying on ice. Then try 10: it reacts instantly and feels twitchy.
    3. 
          
  3. Set Sink to 0 and let go. The plane holds its height forever, and the game loses its tension.
    4. 
        

      

      

        
Where it came from

        
    
          
  • Scramble (1981) and most early side-scrollers moved the ship directly: press up and it moves up at a fixed speed, with no momentum.
    • 
          
  • Helicopter games, and later Flappy Bird (2013), made "hold or tap to push up, gravity pulls you down" the whole game.
    • 
          
  • Velocity plus drag is how flight simulators and racing games make weight feel real. A heavier plane gets less push and less drag, so it's slower to start and slower to stop.

      LAB 3 · scripts/check-labyrinth.mjs + labyrinth-maps.ts
      
Pour paint to prove a maze can be finished

      
The checker doesn't play the game. It "pours paint" from the start tile. Each wave spreads one tile further, and walls, lava and trapdoors stop it. A door holds the paint back until a key of its colour has been painted. When nothing new can be reached, it looks at what stayed dry. A dry gem, key or exit means the level can't be finished.

check-labyrinth.mjs, the heart of the "can it be finished?" check (shortened)

      
// Walk out from P like spilled water. Walls, lava, fire jets and trapdoors are blocked.
// A door blocks you until you have reached a key of its colour; then it opens.
const blocked = (c) => c === "#" || c === "~" || c === "F" || c === "T";
for (let k = 0; k < 4; k++) {          // look down, left, right, up
  const t = at(x + DX[k], y + DY[k]);
  if (seen.has(id) || blocked(t)) continue;  // dry wall or already wet: skip
  if (t === "R" || t === "B") { waiting[t].push(...); continue; } // door: wait for a key
  seen.add(id); queue.push([nx, ny]);   // paint it, and spread from it next wave
}
// then: every gem, key, the exit key spot and the exit must be in `seen`, or it's a problem.

    

    

      

        
Try this

        
    
          
  1. Pour the Garden Maze as drawn. Read the furthest-step number. That's the longest walk in the maze.
    2. 
          
  2. Wall off the corridor in front of one gem and pour again. The checker names that gem's column and row, the same way the real script does.
    3. 
          
  3. Pick The Dungeon and slow it to 3 waves a second. Watch the paint stop at a door, then flow on once the key has been painted.
    4. 
          
  4. Try the four flips. The game picks one at random each time you play, which is why the checker tests all four.
    5. 
        

      

      

        
Where it came from

        
    
          
  • Edward Moore (1959) described this "spread one step at a time" search for finding the shortest way through a maze. It's now called breadth-first search.
    • 
          
  • C. Y. Lee (1961) used the same waves to route wires on circuit boards. The wave number is the distance, just like the colours here.
    • 
          
  • The paint bucket in MacPaint (1984) and every paint program since is a flood fill too.
    • 
          
  • Zelda (1986) dungeons are key-and-door puzzles. Designers check them with this same "can every key be reached before its door" logic.
